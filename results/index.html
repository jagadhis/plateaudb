Every query is timed on the main thread from call to resolved result: IndexedDB runs on the main thread (no hop); SQLite and plateau run in a dedicated worker and include the postMessage round trip and result clone. Warm = 20 timed runs after an untimed warm-up (100 calls per query shape, 20 for gets, own parameters, interleaved) and one more untimed run. Reopen (`cold`) = close, then open from storage in the same page, then the first Q1; a worker engine keeps its worker (the runtime) and releases only the database and its file handle, as IndexedDB keeps its backend. Fresh page (`fresh`) = a new page load in the same browser context (OPFS and IndexedDB data persist), timed from navigation start (performance.timeOrigin) to the first Q1 result. Every engine gets the same head bootstrap, an inline script in the HTML <head> that runs at navigation before the app bundle loads, and the app's open() attaches to what it started: IndexedDB: issues indexedDB.open(name, 1); open() takes that request (or its result if it already succeeded). SQLite: spawns its worker (a separate script), whose first act is to start loading SQLite's WASM (sqlite3InitModule); open() then installs the OPFS pool and opens the database. plateau: spawns its worker (a separate script) and starts WebAssembly.compileStreaming(fetch(wasm)) on the main thread, posting the Module to the worker to instantiate; open() then takes the file handle and reads the manifest. No bootstrap reads plateau's or SQLite's database file before open(), and nothing caches query results across page loads. Untimed after each run: details, then close. Built files carry content hashes and are served `Cache-Control: immutable` (index.html `no-cache`), as a production host would. `freshFirstLoad` = the same fresh-page runs, done first, each under a new URL prefix so every script and WASM file is fetched from the server at a URL never seen before (empty HTTP and compiled-code caches); `fresh` = repeat loads at the page's own URL, whose files the main run fetched. The OS file cache stays warm in both. `updates` runs last, from a plain page load, on the database the clean runs left: open, then two commits that together replace 1% of rows (an edit: new state, assignee, labels, priority, recent updatedAt, edited title; one in ten also moves team) and delete another 1% (updateBatches: the first commit 1,000 of each, the second the rest), each engine its native way (IndexedDB: one readwrite transaction per commit, put and delete per row, default durability; SQLite: one transaction per commit, UPDATE and DELETE by primary key with the label join rows removed by their primary key; plateau: put of the batch, delete of the ids, save). Each commit is timed on the main thread from the call to its durable end; rows are generated untimed beforehand. Then the warm set and reopens as above (`u_*` signatures), and for the plateau engines compaction followed by the same again (`c_*`, compared with every engine's `u_*`). Loads: IndexedDB and plateau-idb-generic (the same code) commit a readwrite transaction per 10,000-row chunk; SQLite as before; plateau and plateau-idb commit every 50,000 rows and then compact, so the measured runs start from one segment while unsaved rows stay bounded. plateau engines run under the runtime's default memory budget (64 MiB, 24 MiB where navigator.deviceMemory <= 4) unless the engine name carries a variant (`plateau@24mb`, `plateau@unbounded`). `details*` record wasmMemoryBytes (the worker's WASM memory: its peak so far, since WASM memory never shrinks) and fileBytes after the load, after the update commits and after compaction (each before any query), and again after each warm set.
